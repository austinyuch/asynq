# Dashboard normal-return and owned shutdown

Existing quit paths used os.Exit(0), bypassing deferred resource cleanup. Fetch goroutines published unconditionally to unbuffered channels without a cancellation or bounded-admission contract. Normal process exit does kill goroutines; the demonstrated defect is skipped graceful cleanup, not proof that workers survived process exit. IL-013 is folded into the existing reconciliation CR.

Public Run retains terminal creation/initialization behavior, then delegates the initialized screen to private runWithScreen. That path creates an owned Inspector and four-slot dataFetcher; no global mutable factory or cross-module API change is introduced. The private dashboard event loop owns screen/ticker/UI state and handles done or closed event channels by returning. Quit only requests stop; single event-loop ownership permits idempotent stop requests.

Shutdown stops the ticker/admission, closes done, waits for real tcell ChannelEvents completion, closes the owned Inspector, waits for admitted workers, then calls Fini. Results/error channels are never closed while senders may remain. Each publication can select done. Launch admission is nonblocking; saturated operations are skipped until later refresh. Separate task/queue/modal refresh operations can therefore be partial, and no consistent snapshot guarantee is asserted. Done cancels publication, not the context-free Inspector I/O itself; transport termination retains its own timing behavior.

Testing distinguishes true SimulationScreen event-loop/pixel/pump execution, real owned Inspector production wiring on dedicated DB12, and pure capacity/publication/closed-transport contracts. Seeded finite navigation/admission properties and semantic mutants must preserve assertion/cleanup outcomes; bounded binary payload fuzz is scoped to publication identity/cancellation. Neither fake data-source contracts nor simulation proves a real terminal initialization or restoration path.
